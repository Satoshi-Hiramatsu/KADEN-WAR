# 家電戦争グラフィックス制作

## 基準と適用範囲

2026-09-05にユーザーが承認した[6担当の顔原画](../../../assets/portraits/executives-roster-v1.png)が画風の正本。テキストの「16bit」だけから別の画風を作らず、この画像の描き込み量・色・輪郭・陰影を引き継ぐ。ユーザーが今回明示する変更を優先する。

このスキルは `.agents/skills/kaden-war-graphics/` に置くプロジェクト専用スキル。以下の「プロジェクトルート」はこのフォルダの3階層上。OS・ユーザー名に依存する絶対パスを保存しない。

- 原画: [assets/portraits/executives-roster-v1.png](../../../assets/portraits/executives-roster-v1.png)
- 元プロンプト・制作記録: [assets/portraits/README.md](../../../assets/portraits/README.md)
- 担当設定: [担当別ゲーム設計.md](../../../担当別ゲーム設計.md)
- 生成時の文章例: [references/prompts.md](references/prompts.md)

## 共通アートディレクション

- レトロな日本の家電メーカー経営SLG。読み取りやすい、密度のある16bit時代風のドット調イラスト。
- 輪郭は濃い焦げ茶〜墨色。髪・衣服・陰影に段階的な色面と細かなピクセルのまとまりを使う。滑らかな写真・3D・水彩・ベクター調に変えない。
- 暖かいアイボリー、黄土・茶、紺、くすんだ緑、えんじ・紫を中心にした落ち着いた色。肌は暖色で、暗部も形が読める。これは視覚上の目安であり、抽出済みの固定HEXパレットではない。
- 穏やかな正面寄りの光、適度な立体感。強い逆光、ネオン、発光縁取り、劇的な映画風照明、過剰なグラデーションは避ける。
- 装飾的なノイズや画面全体のピクセル化フィルタを足すだけで画風を合わせない。形を作る輪郭と色面を重視する。
- 文字・役職・名前・UI枠は基本的に画像に焼き込まず、ゲーム側で表示する。画像内の文字をユーザーが求めた場合はその指示に従う。
- 時代に合った架空の人物・製品・施設を描く。既存原画は1960〜1980年代の雰囲気。別年代の指定があれば意匠を適応し、共通の描画テイストは保つ。

承認画像は1536×1024のドット調原画であり、厳密な低解像度パレット制限済みスプライトではない。雰囲気の一致と、ゲーム実装用のピクセルグリッド調整を区別する。

## 人物と表情差分

胸上の正方形ポートレートを基本に、頭髪を切らず、顔の大きさ・視線の高さ・余白・背景色を原画に揃える。写実寄りの成人の比率を保ち、ちびキャラや大きなアニメ目へ変更しない。眼鏡・髪型・スーツの色で小さくても見分けられるようにする。

原画は3列×2行、各セル512×512。座標原点は左上。

| ID | 位置 / 原点 | 維持する特徴 |
|---|---|---|
| president | 上段左 / (0, 0) | 白髪交じりの後ろへ流した髪、太い眉、紺スーツ、えんじのネクタイ |
| design | 上段中央 / (512, 0) | 短い黒髪、丸眼鏡、白衣、青いシャツ |
| sales | 上段右 / (1024, 0) | 波打つ茶髪、ベージュスーツ、橙色のネクタイ |
| finance | 下段左 / (0, 512) | 黒いまとめ髪、角眼鏡、深緑スーツ |
| production | 下段中央 / (512, 512) | 短い灰色の髪、幅のある顔、青い作業着 |
| personnel | 下段右 / (1024, 512) | 肩までの栗色の髪、紫系ジャケット |

表情変更では同じ人物の顔立ち・髪型・年齢感・服装・眼鏡・構図を固定し、眉・目・口など指定された表情だけを変える。新人物には原画を画風参照として渡し、既存人物を複製する指示にしない。一人の依頼から6人の一覧を生成しない。

## 家電・施設への展開

顔原画は画風の参照であり、人物や衣服を家電・施設に混ぜない。対象の年代と用途に合わせて形・素材・視点を指定する。家電はシルエットと操作部が小サイズでも分かる構図、施設はゲームで必要な正面・俯瞰などの視点を選ぶ。既存の同カテゴリ素材があれば、それも参照して視点・縮尺を揃える。

顔以外の画風展開は未承認の新作として扱う。原画の承認を新作への承認とみなさないが、通常の制作依頼で事前の再承認を求める必要はない。

## 制作手順

1. 対象・用途・年代・必要点数を依頼と既存素材から読み取る。通常は不足を妥当に補い、追加の人物・表情・別案を勝手に増やさない。
2. 原画を画像表示ツールで実際に確認する。既存人物の編集なら対象画像も確認する。参照画像を読み込めない場合、記憶だけで同一テイストを保証せず、読み込みを回復するか不足を伝える。
3. 内蔵 `image_gen` を使う。利用可能な `imagegen` スキルのツール・保存手順にも従う。ローカル画像は確認後に `referenced_image_paths` で渡し、画風参照・編集対象をプロンプト内で区別する。既存人物の差分では対象セルの位置とIDを明示する。
4. [プロンプト例](references/prompts.md)の共通部と、今回必要な対象部だけを使う。参照画像との一致を優先し、原画にない画風の形容を積み重ねない。別アセットはそれぞれ生成する。一覧シートを求められた場合だけ複数対象を1枚に配置する。
5. 生成結果を原画と比較し、顔立ち・描画密度・色・影・構図・数・切れ・文字混入を確認する。必要な修正は対象を絞った編集で行う。画像編集をコード描画やピクセル化処理で代用しない。
6. 最終画像を必ずプロジェクトの `assets/` 以下へコピーする。承認済み原画は上書きしない。人物は `assets/portraits/<id>-<expression>-vN.png`、製品は `assets/products/<slug>-vN.png`、施設は `assets/facilities/<slug>-vN.png` を基本とし、既存名があれば次の版を選ぶ。
7. 該当素材の台帳にパス・寸法・用途・使用ツール・実際のプロンプト・参照元・確認結果を記録する。生成直後は「作成済み・承認待ち」、明示承認後に「承認済み」とする。実寸表示や透過を確認していなければ、その状態を記す。
8. 保存先と制作結果を簡潔に報告する。ユーザーの依頼が素材制作だけなら、ゲームの機能追加や公開まで広げない。

内蔵ツールが使えない場合は、その状態を伝える。CLI/APIへの切替は明示的に依頼・承認された場合だけ行い、必要なAPIキーはローカル環境で設定してもらう。

## 完了時の確認

- 参照画像が実際に入力され、同じ画風として自然に並ぶか。
- 既存人物の差分なら同じ人物に見えるか。新規対象なら指示した対象と点数か。
- 頭髪・輪郭・製品の主要部が意図せず切れず、小さな表示でも識別できるか。
- 保存先がプロジェクト内で、承認済み原画を残しているか。
- 生成ツール指定の寸法・透過が実際の出力と一致するか。透過を求めた場合は市松模様の描き込みではなくアルファを確認する。
- 未実施のゲーム内表示確認・減色調整・承認を完了扱いにしていないか。
